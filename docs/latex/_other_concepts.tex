\hypertarget{_other_concepts_autotoc_md17}{}\doxysection{\texorpdfstring{CUIInfrastructure}{CUIInfrastructure}}\label{_other_concepts_autotoc_md17}
Most CUI stuff is located in CUICore ~\newline
 CUICore is a passive isolated state machine ~\newline
 It doesn\textquotesingle{}t know about the game and has to be run by CUIRunners via handles ~\newline


There could be various runners, e.\+g. Solo runner runs code in this mod, Master runner scans other mods, test runner can feed it with fake data and concurrent runner can run CUICore in a separate thread\hypertarget{_other_concepts_autotoc_md18}{}\doxysubsubsection{\texorpdfstring{Then why are you putting solo runner in CUI master package?}{Then why are you putting solo runner in CUI master package?}}\label{_other_concepts_autotoc_md18}
\href{https://tenor.com/ru/view/ah-eto-bleh-anime-bleh-gif-26784876}{\texttt{Ah, eto... bleh.\+gif}}

Master runner isn\textquotesingle{}t done yet, and there\textquotesingle{}s not much to scan in other packages yet ~\newline
 Current Solo\+Runner just finds all CUIComponents and ISerializable in assembly that called CUI.\+Start ~\newline
 Should work from master package too

Also data sources are separated from runners

CUICore + CUIRunners + data sources makes CUISetup ~\newline
 There\textquotesingle{}s one static CUISetup at CUI.\+Setup ~\newline
 It\textquotesingle{}s initiated at CUI.\+Start() and automatically disposed at plugin.\+Dispose()

CUI.\+Setup is the singleton here, everything else is just pointing to it

CUI and CUICore classes have static members for accessing core and runners ~\newline
 Why 2? CUI is supposed to be used by you, and CUICore is supposed to be called by stuff from inside CUICore ~\newline
 Also stuff that calls CUICore assumes that it\textquotesingle{}s already activated

 \hypertarget{_other_concepts_autotoc_md19}{}\doxysection{\texorpdfstring{Visual\+Components /\+ Visual\+Units}{Visual\+Components /\+ Visual\+Units}}\label{_other_concepts_autotoc_md19}
Unit of drawing /\+ event handling in CUI is Visual\+Units ~\newline


Simple\+Texture, Borders, Text\+Block are Visual\+Units ~\newline


Visual\+Components is aggregate for Visual\+Units, it\textquotesingle{}s a base class for CUIComponent and other stuff containing Visual\+Units ~\newline
 Visual\+Components have Visual\+Split method where they specify how they should be splitted

CUIMain\+Component recursively splits Visual\+Components into a chain of Visual\+Units ~\newline
 Then it draws them and dispatches events to them ~\newline
 Host Visual\+Component typically listens to events on its Visual\+Units

Also Visual\+Components can yield Visual\+Bounds in Visual\+Split, they are commands for Chain\+Drawer to change its state e.\+g. change scissor rect, sampler state or apply camera transformation before drawing
