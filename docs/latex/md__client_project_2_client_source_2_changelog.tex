prev CUI was hardwired to the game and it\textquotesingle{}s lifecycle

Now all CUI stuff was moved to CUICore, which is passive isolated state machine ~\newline
 It doesn\textquotesingle{}t know about the game and has to be runned by CUIRunners via handles ~\newline
 There can be various runners, e.\+g. they can run code in this mod, or scan other mods, or feed it with test data, or run it in a separate process\hypertarget{md__client_project_2_client_source_2_changelog_autotoc_md67}{}\doxysubsubsection{\texorpdfstring{-\/ CUICore is isolated from Mono\+Game}{-\/ CUICore is isolated from Mono\+Game}}\label{md__client_project_2_client_source_2_changelog_autotoc_md67}
It runs on its own abstraction ~\newline
 Now it\textquotesingle{}s possible to write tests for draw calls and use fake textures with no data\hypertarget{md__client_project_2_client_source_2_changelog_autotoc_md68}{}\doxysubsubsection{\texorpdfstring{-\/ Visual\+Components /\+ Visual\+Elements}{-\/ Visual\+Components /\+ Visual\+Elements}}\label{md__client_project_2_client_source_2_changelog_autotoc_md68}
In prev version the base class for drawn stuff was CUIComponent ~\newline
 So other stuff had to either be based on CUIComponent or copy its code and be processed separately ~\newline
 E.\+g. slider handles, resize handles had to either be child CUIComponent or be so pseudo components manually updated and drawn by host component ~\newline
 There was no way to draw borders above children, because borders was drawn by CUIComponent together with background I had to draw them in a separate draw loop in Draw\+Front method and i had to handle clicks on such handles separately in event loop ~\newline
 And every class derived from CUIComponent had to have borders and other useless stuff

Now the unit of drawing /\+ event handling is Visual\+Element ~\newline
 They are primitives, e.\+g. texture, border, lines, blocks of text ~\newline
 Visual\+Component is almost empty abstract base for all components ~\newline
 Visual\+Component can have many Visual\+Elements and they control their order with Visual\+Split ~\newline
 Events are routed from Visual\+Elements to host components\hypertarget{md__client_project_2_client_source_2_changelog_autotoc_md69}{}\doxysubsubsection{\texorpdfstring{-\/ Text measurement /\+ drawing logic was moved to Text\+Block Visual\+Element}{-\/ Text measurement /\+ drawing logic was moved to Text\+Block Visual\+Element}}\label{md__client_project_2_client_source_2_changelog_autotoc_md69}
So components that needs to draw some text no longer have to be based on CUIText\+Block\hypertarget{md__client_project_2_client_source_2_changelog_autotoc_md70}{}\doxysubsubsection{\texorpdfstring{-\/ Visual\+Bounds}{-\/ Visual\+Bounds}}\label{md__client_project_2_client_source_2_changelog_autotoc_md70}
Visual\+Components can yield enter/\+exit Visual\+Bounds instructions for Chain\+Drawer in Visual\+Split ~\newline
 This allows to apply camera transformation /\+ croping /\+ different sampler state to children /\+ particular Visual\+Elements ~\newline
 Now CUIMap with natural zoom should be possible\hypertarget{md__client_project_2_client_source_2_changelog_autotoc_md71}{}\doxysubsubsection{\texorpdfstring{-\/ Most reflection stuff was moved to code generator}{-\/ Most reflection stuff was moved to code generator}}\label{md__client_project_2_client_source_2_changelog_autotoc_md71}
So i can use funny design patterns without wrecking the performance\hypertarget{md__client_project_2_client_source_2_changelog_autotoc_md72}{}\doxysubsubsection{\texorpdfstring{-\/ Everything was public}{-\/ Everything was public}}\label{md__client_project_2_client_source_2_changelog_autotoc_md72}
There\textquotesingle{}s a lot of internal logic, and it\textquotesingle{}s impossible to maintain in one big object ~\newline
 So i had to split them, but then those objects had to touch internals of each other -\/\texorpdfstring{$>$}{>} internals had to be public ~\newline
 And anything could potentially reference and depend on anything (and it did) ~\newline


Now there\textquotesingle{}s funny compiler generated component level dependency injection system that allows me to keep logic in private modules that require each other via interfaces and are injected into each other by host component\hypertarget{md__client_project_2_client_source_2_changelog_autotoc_md73}{}\doxysubsubsection{\texorpdfstring{-\/ Layout calculations use Rect\+Float while Drawing uses Rect\+Int}{-\/ Layout calculations use Rect\+Float while Drawing uses Rect\+Int}}\label{md__client_project_2_client_source_2_changelog_autotoc_md73}
In prev version rects was rounded on every step of layout calculations ~\newline
 And it caused double rounding issues all over the place, e.\+g. ladder walking components in nested lists

Now layout is calculated on Rect\+Float and gets rounded only on the last stage before drawing\hypertarget{md__client_project_2_client_source_2_changelog_autotoc_md74}{}\doxysubsubsection{\texorpdfstring{-\/ Debug system rework}{-\/ Debug system rework}}\label{md__client_project_2_client_source_2_changelog_autotoc_md74}
This is actually was the last straw that killed prev version:\+ ~\newline
 You had to create debug string for each event even if the node was off which killed the fps ~\newline
 And CUI was using one hardcoded debugger which wasn\textquotesingle{}t flexible enough ~\newline
 And when i touched it, it fell appart and then there was no other way to debug the debugger or anything

new Debug\+Nodes don\textquotesingle{}t create event objects when they\textquotesingle{}re off ~\newline
 They are routable, so i can enable them for some types of events or groups of components ~\newline
