0.3.0.0

Rewritten from scratch

Fixes:

- Isolated CUICore

prev CUI was hardwired to the game and it's lifecycle

Now all CUI stuff was moved to CUICore, which is passive isolated state machine
It doesn't know about the game and has to be runned by CUIRunners via handles
There can be various runners, e.g. they can run code in this mod, or scan other mods, or feed it with test data, or run it in a separate process

- CUICore is isolated from MonoGame

It runs on its own abstraction
Now it's possible to write tests for draw calls and use fake textures with no data

- VisualComponents / VisualElements

In prev version the base class for drawn stuff was CUIComponent
So other stuff had to either be based on CUIComponent or copy its code and be processed separately
E.g. slider handles, resize handles had to either be child CUIComponent or be so pseudo components manually updated and drawn by host component
There was no way to draw borders above children, because borders was drawn by CUIComponent together with background I had to draw them in a separate draw loop in DrawFront method and i had to handle clicks on such handles separately in event loop
And every class derived from CUIComponent had to have borders and other useless stuff

Now the unit of drawing / event handling is VisualElement
They are primitives, e.g. texture, border, lines, blocks of text
VisualComponent is almost empty abstract base for all components
VisualComponent can have many VisualElements and they control their order with VisualSplit
Events are routed from VisualElements to host components

- Text measurement / drawing logic was moved to TextBlock VisualElement

So components that needs to draw some text no longer have to be based on CUITextBlock

- VisualBounds

VisualComponents can yield enter/exit VisualBounds instructions for ChainDrawer in VisualSplit
This allows to apply camera transformation / croping / different sampler state to children / particular VisualElements
Now CUIMap with natural zoom should be possible

- Most reflection stuff was moved to code generator

So i can use funny design patterns without wrecking the performance

- Everything was public

There's a lot of internal logic, and it's impossible to maintain in one big object
So i had to split them, but then those objects had to touch internals of each other -> internals had to be public
And anything could potentially reference and depend on anything (and it did)

Now there's funny compiler generated component level dependency injection system that allows me to keep logic in private modules that require each other via interfaces and are injected into each other by host component

- Layout calculations use RectFloat while Drawing uses RectInt

In prev version rects was rounded on every step of layout calculations
And it caused double rounding issues all over the place, e.g. ladder walking components in nested lists

Now layout is calculated on RectFloat and gets rounded only on the last stage before drawing

- Debug system rework

This is actually was the last straw that killed prev version:
You had to create debug string for each event even if the node was off which killed the fps
And CUI was using one hardcoded debugger which wasn't flexible enough
And when i touched it, it fell appart and then there was no other way to debug the debugger or anything

new DebugNodes don't create event objects when they're off
They are routable, so i can enable them for some types of events or groups of components
They are sending debug events to debug hub where debuggers can listen for them So i can make different debuggers / swap them, one faulty debugger won't break the whole debug system

- other stuff i'm too lazy to mention

New issues:

  • inconsistency
  • poor error handling and validation
  • a lot of stuff from prev version still missing

0.2.6.0

Found one ugly solution to the curse (https://github.com/evilfactory/LuaCsForBarotrauma/issues/245), i think it's the only way to bypass it
If you find a better way let me know

So, the problem is harmony patches in assembly mods are bugged and generally don't work

Solution: Add lua script that adds patches and calls hooks, and then add hooks from assembly

If you set CUI.UseCursedPatches to true it'll use harmony and be potentially bugged
If you set CUI.UseCursedPatches to false it won't be bugged, but you'll also have to set CUI.HookIdentifier to some name or hooks from different CUIs will conflict and add AdditionalHooks.lua to Lua/Autorun

Buttons now will folow a pattern: if state is changed by user input then it'll invoke StateChanged event
If state is changed from code then it won't invoke the event

When you change state from code you already know about that so you don't need an event
